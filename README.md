# 溪影尋蹤｜Web APP

## 開啟方式
1. 解壓縮 ZIP。
2. 使用 WebStorm 開啟 `xiying_app` 資料夾。
3. 以本機伺服器或 Netlify HTTPS 網址開啟 `index.html`。

## 本版基礎功能
- 響應式手機介面。
- Firebase 匿名登入。
- 建立／加入線上房間與等待室同步。
- 房主至少 4 人才能開始。
- 所有裝置同步 20 秒魚類圖鑑倒數及階段切換。

## 最新規則
請閱讀 `GAME_RULES_V3.3.md`。APP 內「遊戲玩法說明」也已更新為 V3.3：40 張唯一 ID 實體卡、每人抽 5 張、系統隨機抽牌方向、抽完後自由 AR 掃描、公開情報桌面、A/B 路線、棄牌回池及玩家交換規則。

## 重要：目前尚未完成的功能
本版不是完整多人遊戲版。Firebase 目前只支援房間與同步開始流程。下列功能仍待開發：
- 40 張實體卡牌完整資料與唯一 ID 對照表。
- 現場座位順序輸入及同步、隨機抽牌方向同步。
- 每人抽 5 張的實體抽牌確認與多人同步。
- AR/Vuforia 掃描事件寫入、驗證與 0/5～5/5 進度。
- 公開情報桌面即時同步。
- 棄牌回池、再次抽取及卡牌歷史。
- 玩家交換請求、雙方選卡、交換次數及原子性持有人轉移。
- A/B 路線與勝利判定的可信任後端同步。

請勿把前端手動輸入卡號視為真實 AR 辨識，也不要把前端傳入的驗證結果當成可信任結果。

## 尚待確認
- 棄牌回到卡池後，立即可抽或下一輪才可抽。
- 40 張卡牌實際內容、類別及適用魚種。
- 抽牌、棄牌與交換的完整回合限制。

## Firebase 設定
沿用專案內 `firebase-sync.js` 的 Firebase Web 設定。正式部署前請檢查 Realtime Database Rules，勿使用對所有登入使用者開放任意讀寫的規則。正式遊戲交易與勝利判定應放在可信任後端。


## 單人測試模式（本次修改）
- `firebase-sync.js` 已啟用 `SINGLE_PLAYER_TEST_MODE = true`。
- 房主建立房間後，只有自己 1 人也能按「開始遊戲」。
- 保留 Firebase 線上房間、房主權限與 20 秒圖鑑倒數同步流程。
- 正式規則仍是 4～6 人；測試完成後，將 `SINGLE_PLAYER_TEST_MODE` 改為 `false` 即恢復至少 4 人才能開始。
- 注意：此版本放寬的是「開始遊戲人數門檻」，不代表發牌、抽換卡、猜測與勝利狀態已完成跨裝置同步。


## 兒童友善介面改版

## V3：開局五張情報卡與掃描框
- 開局發牌調整為每位玩家直接取得 5 張情報卡。
- 情報卡頁面文字同步改為「開局已取得 5 張」。
- 掃描頁新增相機取景預覽、四角掃描定位框、掃描步驟及開關相機控制。
- 相機預覽透過瀏覽器 getUserMedia；目前尚未加入 QR Code 解碼或 Vuforia 辨識，手動輸入卡號仍為測試流程。
- 相機功能需在 HTTPS 網站或 localhost 使用，並由使用者允許相機權限。


## V4 卡片圖片掃描介面修正
- 我的情報卡頁面加入明顯的卡片掃描區與相機取景框。
- 取景框比例改為直式實體卡片，提示必須讓整張卡面與四個角完整入鏡。
- 移除 QR Code 作為掃描目標的說明；預期辨識方式為 Vuforia Image Target／卡面圖片辨識。
- 相機目前只負責即時預覽與取景；真正圖像辨識仍需 Unity/Vuforia 端接入並回傳辨識結果。
- 測試用卡片選擇器可選擇自己持有的卡片，按下後標記原型測試驗證。
